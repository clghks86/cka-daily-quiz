1클러스터 아키텍처 한눈에▾

컨트롤 플레인의 네 컴포넌트는 모두 정적 파드로 뜹니다. 매니페스트는 /etc/kubernetes/manifests/ 에 있고, kubelet이 이 디렉터리를 감시합니다. etcd와 직접 통신하는 것은 kube-apiserver 하나뿐입니다.

컴포넌트형태역할
kube-apiserver정적 파드모든 요청의 관문, etcd의 유일한 클라이언트
etcd정적 파드클러스터 상태 KV 저장소 (2379)
kube-scheduler정적 파드파드를 어느 노드에 둘지 결정
kube-controller-manager정적 파드컨트롤러 루프 (Deployment→ReplicaSet 등)
kubeletsystemd 서비스노드마다 상주, 파드 실행·상태 보고
kube-proxyDaemonSetService 트래픽 규칙 (iptables/IPVS)
시험 포인트 — 정적 파드는 kubectl edit·kubectl delete 로 고쳐지지 않습니다. 반드시 매니페스트 파일을 직접 수정하고, kubelet이 다시 읽어 파드를 재생성할 때까지 기다립니다.

빠른 확인

kubectl get pods -n kube-system
kubectl get nodes -o wide
ls /etc/kubernetes/manifests/
sudo crictl ps | grep -E 'etcd|apiserver'
2etcd 백업 — snapshot save▾

etcd는 2379 포트에서 mTLS로 통신합니다. 그래서 --endpoints 와 CA·서버 인증서·서버 키 세 개를 항상 함께 넘겨야 합니다. 인증서 경로는 /etc/kubernetes/manifests/etcd.yaml 에서 그대로 복사하면 틀리지 않습니다.

sudo ETCDCTL_API=3 etcdctl snapshot save /opt/backup/etcd-$(date +%F).db \
  --endpoints=https://127.0.0.1:2379 \
  --cacert=/etc/kubernetes/pki/etcd/ca.crt \
  --cert=/etc/kubernetes/pki/etcd/server.crt \
  --key=/etc/kubernetes/pki/etcd/server.key

저장한 파일은 바로 검증합니다. revision·totalKey 이 보이면 정상입니다.

sudo ETCDCTL_API=3 etcdctl snapshot status /opt/backup/etcd-2026-11-19.db --write-out=table

건강 상태·멤버 확인

sudo ETCDCTL_API=3 etcdctl endpoint health \
  --endpoints=https://127.0.0.1:2379 \
  --cacert=/etc/kubernetes/pki/etcd/ca.crt \
  --cert=/etc/kubernetes/pki/etcd/server.crt \
  --key=/etc/kubernetes/pki/etcd/server.key

sudo ETCDCTL_API=3 etcdctl member list --write-out=table
주의 — 복구 연습은 반드시 백업이 있는 상태에서. snapshot save 없이 restore 부터 하면 클러스터를 되돌릴 수 없습니다.
3etcd 복구 — restore 5단계▾

복구는 "etcd를 멈추고 → 새 데이터 디렉터리로 복원하고 → 매니페스트가 그 디렉터리를 보게 바꾸고 → 다시 띄운다" 순서입니다.

# 1) etcd 정적 파드 내리기 (매니페스트를 잠시 옮긴다)
sudo mv /etc/kubernetes/manifests/etcd.yaml /tmp/etcd.yaml.bak

# 2) 새 디렉터리로 복원 (기존 /var/lib/etcd 는 비워 두거나 건드리지 않는다)
sudo ETCDCTL_API=3 etcdctl snapshot restore /opt/backup/etcd-2026-11-19.db \
  --data-dir=/var/lib/etcd-restore

# 3) 매니페스트에서 두 곳 수정
#    - command 의 --data-dir=/var/lib/etcd-restore
#    - volumes 의 hostPath.path: /var/lib/etcd-restore
sudo vi /etc/kubernetes/manifests/etcd.yaml

# 4) 매니페스트 되돌리기 → kubelet 이 파드를 다시 만든다
sudo mv /tmp/etcd.yaml.bak /etc/kubernetes/manifests/etcd.yaml

# 5) 확인 (apiserver 도 같이 살아나야 한다)
sudo crictl ps | grep etcd
kubectl get pods -n kube-system
sudo ETCDCTL_API=3 etcdctl endpoint health --endpoints=https://127.0.0.1:2379 \
  --cacert=/etc/kubernetes/pki/etcd/ca.crt \
  --cert=/etc/kubernetes/pki/etcd/server.crt \
  --key=/etc/kubernetes/pki/etcd/server.key
가장 많이 하는 실수 — --data-dir 만 바꾸고 volumes.hostPath.path 를 그대로 두는 것. 컨테이너는 여전히 옛 경로를 마운트해서 복구가 반영되지 않습니다. 두 곳 모두 바꿔야 합니다.

etcd가 내려간 동안에는 apiserver가 응답하지 않으므로 kubectl 이 먹통이 됩니다. 이때는 crictl 과 매니페스트 편집으로 진행합니다.

4kubeadm 클러스터 업그레이드▾

순서는 컨트롤 플레인 → 워커, 그리고 각 노드 안에서는 kubeadm → kubelet/kubectl 입니다. 마이너 버전은 건너뛸 수 없고 한 번에 하나씩 올립니다.

공통 준비

sudo apt-get update
sudo apt-mark unhold kubeadm
sudo apt-get install -y kubeadm=1.31.4-1.1
sudo apt-mark hold kubeadm
kubeadm version -o short

# 업그레이드 가능한 버전과 컴포넌트 상태 확인 (변경은 없음)
sudo kubeadm upgrade plan

첫 컨트롤 플레인 노드

# 워크로드 보호를 위해 먼저 비운다
kubectl drain controlplane --ignore-daemonsets --delete-emptydir-data

sudo kubeadm upgrade apply v1.31.4
# "SUCCESS! Your cluster was upgraded to v1.31.4" 확인

추가 컨트롤 플레인 · 워커 노드

kubectl drain node1 --ignore-daemonsets --delete-emptydir-data
sudo kubeadm upgrade node

kubelet · kubectl 올리기 (모든 노드)

sudo apt-mark unhold kubelet kubectl
sudo apt-get install -y kubelet=1.31.4-1.1 kubectl=1.31.4-1.1
sudo apt-mark hold kubelet kubectl
sudo systemctl daemon-reload
sudo systemctl restart kubelet

kubectl uncordon node1
# 노드별 버전 확인
kubectl get nodes -o wide
kubectl version --short
명령 구분 — kubeadm upgrade apply 는 첫 컨트롤 플레인 노드에서만. 추가 컨트롤 플레인과 모든 워커는 kubeadm upgrade node 입니다.
5시험 함정 체크리스트▾
  • kubeadm은 마이너 버전을 건너뛰지 못한다 — v1.29 → v1.30 → v1.31
  • kubelet은 kube-apiserver보다 높은 버전일 수 없다 (최대 3 마이너 낮음)
  • etcd 백업 명령에는 --endpoints, --cacert, --cert, --key 네 가지가 다 필요
  • 복구 후 --data-dir 과 hostPath.path 둘 다 수정
  • 정적 파드는 매니페스트 파일로만 수정 (kubectl edit 불가)
  • drain 시 --ignore-daemonsets, emptyDir가 있으면 --delete-emptydir-data
  • 업그레이드 끝나면 kubectl uncordon — 잊으면 채점에서 감점
  • 명령은 sudo 로, 작업은 가능하면 kubectl 대신 실제 노드에서 직접

참고: ETCDCTL_API=3 은 etcd 3.5 이상에서 기본값이지만, 시험 환경에서 습관처럼 붙이는 편이 안전합니다.
